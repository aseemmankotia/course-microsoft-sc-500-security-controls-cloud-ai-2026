## Chapter 5: Network Perimeter Controls: NSGs, Azure Firewall, WAF, DDoS — Flashcards

| # | Front (Question) | Back (Answer) |
|---|-----------------|---------------|
| 1 | NSG custom security rule priority range? | 100–4096 (lower number = higher priority, evaluated first). Exam tip: default rules sit at 65000+ and always evaluate last unless overridden by a custom rule with a lower number. |
| 2 | NSG default rule priorities (inbound)? | AllowVNetInBound=65000, AllowAzureLoadBalancerInBound=65001, DenyAllInBound=65500. Exam tip: these can't be deleted, only overridden by a lower-priority custom rule. |
| 3 | Default max security rules per NSG? | 1000 rules (default limit, can be raised via support request up to 4096). Exam tip: exceeding this without requesting an increase causes deployment failures. |
| 4 | NSG vs ASG — when to use each? | NSG rules filter by IP/port/protocol; ASGs group VM NICs by role (e.g., 'WebTier') so rules scale automatically as VMs are added/removed. Exam tip: ASGs are the answer when the scenario says 'without updating rules as VMs scale.' |
| 5 | Azure Firewall SKU tiers and key differentiator? | Basic: SMB/branch, ~250 Mbps. Standard: FQDN filtering, threat intel Alert/Deny, up to 30 Gbps. Premium: adds TLS inspection, IDPS, URL filtering, web categories, up to 100 Gbps. Exam tip: choose Premium only when TLS inspection/IDPS is explicitly required. |
| 6 | WAF: Detection mode vs Prevention mode | Detection = logs matches only, no blocking (used for tuning). Prevention = blocks and logs matching requests. Exam tip: scenario says 'test rules without impacting production' → Detection. |
| 7 | WAF on Application Gateway vs Front Door — scope? | Application Gateway WAF = regional, Layer 7, VNet-integrated. Front Door WAF = global, edge/CDN-based, lowest latency for worldwide users. Exam tip: 'global users, low latency' points to Front Door. |
| 8 | OWASP rule set naming for Application Gateway vs Front Door WAF? | Application Gateway uses OWASP Core Rule Set (CRS), current version 3.2. Front Door uses the Default Rule Set (DRS), current version 2.1. Exam tip: both are OWASP Top 10-based but named differently per product. |
| 9 | Azure Firewall Threat Intelligence modes? | Off, Alert only (logs match, allows traffic), Alert and Deny (logs match, blocks traffic). Exam tip: 'Alert and Deny' is required whenever the scenario needs traffic to malicious IPs/domains actually blocked. |
| 10 | DDoS Protection tiers: Basic vs Network Protection vs IP Protection? | Basic: free, automatic, platform-level only. Network Protection: VNet-scoped, ML-tuned, includes cost protection SLA + Rapid Response team. IP Protection: pay-per-IP, lower cost, no cost protection SLA. Exam tip: 'cost protection SLA + Rapid Response' = Network Protection. |
| 11 | Hub-spoke network segmentation pattern — purpose? | Hub VNet hosts shared services (Azure Firewall, VPN/ExpressRoute gateway); spoke VNets (workloads) peer to hub and route traffic through it for centralized inspection/logging. Exam tip: correct answer when scenario needs centralized traffic inspection across multiple VNets. |
| 12 | NSG rule evaluation order behavior? | Rules process in ascending priority order; the FIRST matching rule is applied and evaluation STOPS (no further rules checked). Exam tip: common trap is assuming all matching rules are combined — only the first match wins. |
