## Chapter 9: App Service, Serverless & Key Vault Secrets Management — Flashcards

| # | Front (Question) | Back (Answer) |
|---|-----------------|---------------|
| 1 | Azure Key Vault soft-delete retention period range? | 7–90 days, default 90. Mandatory since 2020 — cannot be disabled. Exam tip: soft-delete alone does NOT prevent purge; purge protection is required to block permanent deletion. |
| 2 | How long does purge protection block a Key Vault purge, and can it be disabled once enabled? | Blocks purge for the full soft-delete retention period (up to 90 days); cannot be bypassed by ANY role including Owner. Once enabled, purge protection CANNOT be disabled. |
| 3 | Key Vault access policies vs Azure RBAC — key difference? | Access policies = whole-vault, object-type permissions (keys/secrets/certs), no sub-vault scoping. RBAC = Azure AD role assignments scoped to resource/RG/subscription, auditable via PIM/Activity Log. Exam tip: a vault uses ONE model at a time (enableRbacAuthorization property). |
| 4 | Secure pattern for App Service to read a Key Vault secret with zero code changes? | Enable System-assigned Managed Identity → grant 'Key Vault Secrets User' RBAC role (or Get/List access policy) → reference secret in App Setting via @Microsoft.KeyVault(...). Exam tip: app restart often needed after granting new permission for the reference to resolve. |
| 5 | App Service Key Vault reference syntax that ALWAYS resolves to the latest secret version? | @Microsoft.KeyVault(VaultName=myvault;SecretName=mysecret) — omit version. Exam tip: including a SecretUri with a version pins the reference; omitting version auto-updates after rotation. |
| 6 | Name 3 built-in RBAC roles for Key Vault data plane. | Key Vault Administrator (full data-plane mgmt), Key Vault Secrets User (read secret values only), Key Vault Reader (read metadata, no secret values). Exam tip: 'Secrets User' cannot set/delete secrets — that's 'Secrets Officer'. |
| 7 | How does an Azure Function connect to Storage without a connection string? | Enable Managed Identity on the Function App, assign a data-plane RBAC role (e.g., Storage Blob Data Owner) on the target resource, then configure the binding with identity-based connection settings (e.g., '<CONNECTION>__serviceUri' + 'Credential=ManagedIdentity'). Exam tip: this is the recommended practice over storing connection strings. |
| 8 | When does Key Vault auto-renew a certificate? | Per the lifetime action in the certificate policy — typically at a percentage of lifetime elapsed or a fixed number of days before expiry. Exam tip: auto-renewal requires an integrated CA issuer; self-signed certificates are NOT auto-renewed. |
| 9 | What is App Service Authentication ('Easy Auth')? | Built-in auth/authz module running as a platform-level sidecar; supports Azure AD, Google, Facebook, etc. with NO code changes required. Exam tip: it caches tokens in a token store and can be combined with 'Allow unauthenticated access' for selectively securing routes. |
| 10 | Most secure Key Vault network config while still allowing trusted Azure services (e.g., Backup)? | Private Endpoint deployed + Public network access = Disabled + 'Allow trusted Microsoft services to bypass this firewall' = Yes. Exam tip: trusted-services bypass is a firewall setting independent of the private endpoint configuration. |
| 11 | Two time settings in a Key Vault key rotation policy? | Expiry time (e.g., 90 days — when a new version auto-generates if action=Rotate) and Notify time (e.g., 30 days before expiry — fires an Event Grid event). Exam tip: native rotation policies apply to KEYS; SECRETS rotation requires custom Event Grid + Function automation. |
| 12 | Azure CLI property to view/change a Key Vault's permission model? | az keyvault update --enable-rbac-authorization true\|false. Exam tip: switching this flips the ENTIRE vault's permission model — existing access policies are ignored once RBAC is enabled, and vice versa. |
